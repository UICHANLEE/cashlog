# Cashlog 사용자 활동 로그 운영 가이드

## 무엇을 볼 수 있나

Cashlog는 다음 제품 이벤트를 `/uichan` 관리자 화면에서 조회합니다.

- 페이지·앱 화면 방문
- 화면이 실제로 보인 체류시간, 최대 스크롤 깊이
- 화면 진입 후 첫 버튼·링크 조작까지 걸린 시간과 클릭 순서
- 폼 입력 시작과 제출 여부
- 로그인·회원가입·비밀번호 재설정의 시작, 성공, 실패
- 카메라 열기, 사진·영상 선택, 분석 시작·성공·실패와 사용자 체감 처리시간
- 서버 전체 처리시간, 모델 판독시간, 전처리·네트워크 시간, 응답 상태
- 모델·파이프라인별 신뢰도와 추천 카테고리의 사용자 수용·수정 여부
- 가계부 기록 저장, 하루·한 달 스토리 열기와 첫 화면·첫 미디어 준비시간
- 기록·달력·캐릭터 화면 전환 후 첫 화면 표시시간
- 캐릭터 상호작용과 꾸미기
- 사전예약 제출, 프로필 수정, 회원탈퇴
- 브라우저에서 처리되지 않은 오류

조회 화면에는 최근 24시간 이벤트, 활성 세션, 평균 화면 체류시간, 첫 행동까지 걸린 시간, 화면별 첫 행동률과 버튼별 클릭 순위가 표시됩니다. 운영 영역에서는 사진 분석 성공률, P50/P95, 모델 판독 P95, 카테고리 수용률, 기능별 처리시간, 모델·카테고리별 수정률, 하루·한 달 스토리 표시시간을 확인할 수 있습니다. 기간과 이벤트 종류로 원본 이벤트를 필터링할 수도 있습니다.

체류시간은 브라우저 탭이 실제로 보인 구간만 합산합니다. 앱 내부의 기록·달력·캐릭터 탭은 URL이 같아도 별도 화면으로 구분합니다. 첫 행동 시간은 페이지 또는 앱 화면이 열린 뒤 최초의 안전한 버튼·링크 식별자가 조작될 때까지의 표시 시간입니다.

사진 분석은 사진 선택 직후부터 추천 결과가 UI에 반영될 때까지를 `duration_ms`로 기록합니다. 서버가 제공한 `Server-Timing` 응답에서 서버 전체와 모델 판독 시간을 별도로 읽고, 같은 `trace_id`와 `server_request_id`로 브라우저·Vercel·Catai 로그를 연결합니다. 스토리는 첫 화면 표시와 첫 이미지·영상 준비 완료를 별도 이벤트로 측정합니다.

각 이벤트는 IndexedDB 아웃박스에 먼저 기록됩니다. 서버가 저장 성공을 응답한 뒤에만 기기에서 제거하며 실패하면 지수 백오프로 다시 보냅니다. `client_event_id` 고유 제약으로 재전송된 이벤트는 한 번만 저장됩니다. 모든 이벤트에는 배포 커밋 기반 `release`가 붙어 버전별 회귀를 비교할 수 있습니다.

`카테고리 수용률`은 사용자가 모델 추천을 수정하지 않고 저장한 비율입니다. 별도의 `맞아요 / 다시 고를게요` 평가와 추천→최종 카테고리 혼동표도 함께 보며, 같은 분석의 평가를 바꾸면 마지막 선택만 집계합니다. 이 수치 역시 실제 정답 라벨 정확도와는 다릅니다. 진짜 Top-1 정확도는 동의받은 검수 데이터셋과 정답 라벨 평가가 필요합니다.

## 수집하지 않는 정보

제품 사용 로그에는 아래 값을 넣지 않습니다.

- 가계부 금액, 제목, 메모
- 사진·영상 원본, 저장 경로, 공개 URL
- 위도·경도와 장소명
- 이메일, 닉네임, 비밀번호, 인증 토큰
- 사용자가 입력한 자유 형식 텍스트
- OCR 원문, 탐지한 상품명과 사진 내용
- 클릭 좌표, 마우스 이동, 키 입력 내용, 버튼에 표시된 문구

이 기능은 세션 리플레이나 화면 녹화를 하지 않습니다. 클릭 대상은 `record.camera.primary` 같은 개발자가 지정한 고정 식별자 또는 개인정보가 포함되지 않는 요소 메타데이터로만 기록합니다.

클라이언트와 서버가 각각 값을 제한합니다. 서버의 허용 목록에 없는 속성은 요청에 포함되어도 DB에 저장되지 않습니다. 세션 ID는 HMAC-SHA256으로 해시한 뒤 저장하며 원본 IP는 제품 로그 테이블에 저장하지 않습니다.

## 배포 설정

1. Supabase SQL Editor에서 `supabase/migrations/202608030001_user_event_logs.sql`을 실행합니다.
2. 이어서 `supabase/migrations/202608140001_behavior_analytics.sql`을 실행합니다. 기존 이벤트 테이블은 유지되고 행동 분석 집계 함수만 확장됩니다.
3. 이어서 `supabase/migrations/202608180001_operational_analytics.sql`을 실행합니다. 기존 행은 유지되고 운영 인덱스와 관리자 집계 함수만 확장됩니다.
4. 이어서 `supabase/migrations/202608180002_operational_analytics_hardening.sql`을 실행합니다. 이벤트 중복 방지 열과 흐름 기반 완료·이탈 집계를 추가합니다.
5. Vercel 프로젝트의 Settings → Environment Variables에 아래 서버 전용 변수를 Production, Preview에 추가합니다.

```env
CASHLOG_ADMIN_EMAILS=owner@example.com
ANALYTICS_HASH_SALT=<32자 이상의 별도 무작위 문자열>
```

기존 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `AUTH_RATE_LIMIT_SALT`도 유지해야 합니다. 위 두 값에는 `VITE_`를 붙이지 않습니다.

무작위 값은 로컬 터미널에서 만들 수 있습니다.

```bash
openssl rand -base64 48
```

6. Vercel을 다시 배포합니다. 빌드 시점 이후에 추가한 환경변수는 기존 배포에 자동 적용되지 않습니다.
7. `CASHLOG_ADMIN_EMAILS`에 적은 이메일로 `/login.html`에서 로그인합니다.
8. `/uichan`으로 이동해 연결 상태, 사용자 활동 로그와 운영 성능을 확인합니다.

설정이 없으면 관리 API는 `503`, 로그인이 없으면 `401`, 허용 목록 밖의 계정은 `403`으로 닫힙니다. `/uichan` HTML 자체는 열릴 수 있지만 로그 데이터는 인증된 관리자 API에서만 반환됩니다.

## 데이터 위치와 보존

- 원본 이벤트: Supabase Table Editor → `cashlog_event_logs`
- 앱 운영 화면: `/uichan`
- 서버 함수 실행·오류: Vercel Dashboard → Logs

Vercel 로그에는 `vision_analysis_completed` 또는 `image_analysis_completed` 구조화 로그가 남으며 요청 ID, HTTP 상태, 구간별 처리시간만 포함합니다. 사진, OCR, 금액과 사용자 입력은 출력하지 않습니다.

제품 이벤트는 90일 보관을 기본으로 합니다. 조회 요청은 데이터를 변경하지 않으므로 Supabase Dashboard의 Cron에서 하루 한 번 아래 RPC를 실행하도록 예약해야 합니다.

```sql
select public.cashlog_prune_event_logs(90);
```

회원탈퇴 시 해당 계정에 연결된 제품 이벤트도 `cashlog_delete_account_data`에서 삭제합니다. 익명 세션 로그는 특정 사용자와 연결할 수 없으므로 90일 보존정책으로 자동 파기합니다.

## 사용자 선택권

첫 방문에서는 사용성 로그가 꺼져 있으며 사용자가 `허용`을 선택한 뒤부터 제품 이벤트를 보냅니다. 계정 메뉴에서 언제든 다시 끌 수 있고 브라우저의 Do Not Track도 존중합니다. 이 설정은 브라우저별로 저장됩니다. 로그인 중 수집된 이벤트는 계정 식별자와 연결될 수 있으며, 화면 문구와 개인정보처리방침에서 이를 안내합니다. Vercel 같은 호스팅 사업자가 보안과 장애 대응을 위해 생성하는 인프라 로그는 제품 이벤트와 별개입니다.
